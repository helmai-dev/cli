## Key discussion points

### Terminal stays invisible

Helm is already active as soon as a wrapped session starts (Codex and Claude hooks). Josh asked whether to print a per-chat TLDR of what Helm did. Ben: no. Developers did not buy a status feed; they bought a tool that stays out of the way. Analytics, savings, and “what Helm did” live on the dashboard. The terminal should stay quiet.

### Two readers, one product

- **CFO / CEO**: is this saving money on AI tokens, and can you prove it.
- **Engineering manager**: is the team still shipping, and is Helm helping rather than blocking.

Engineers and EMs have to trust accuracy and non-interference first. Once that is true, the CFO cares about token spend and proof. Role-based copy (bigger picture for a CTO, file-level for an EM) was floated; it is not built.

### Opportunities are the adoption feature

The “More identified $0.03 / 27 open opportunities” pairing is wrong as a story. Most of those 27 are unpriced model-mix and overlap cards. The 3 cents is only measured re-billed context. Users need to **action** opportunities — that is how Helm saves more (and how Helm makes money). Clicking Apply today records a team decision. It does not change models, prompts, or routing.

### Model switches vs ongoing savings

Alerting “you used a pricier model than this project already uses” is valuable. Charging the whole project’s delta as Helm-saved is a pushback magnet (“we could have switched ourselves”). Frame it as **context-relevant model choice**, not a model picker. After an accepted switch, watch stored spend on that workload (a bake-off), but do not invoice the full counterfactual. Ongoing levers (reuse, compression, not loading every MCP schema) are cleaner to attribute.

Future: after enough accepted suggestions, autopilot for certain tasks. Not now.

### MCP tool search

Claude Code, unwrapped, loads every connected MCP tool schema on every prompt. Helm wrap sets `ENABLE_TOOL_SEARCH=true` so tools are requested only when needed. This is a real save (Josh’s new-laptop / Opus compacting story; Ben’s Crossbeam-on-every-prompt story). It is not on the dashboard today.

### Coverage Josh described on the call vs code

Wrappers that actually intercept the model path today: **Claude Code and Codex**. Hooks + MCP also cover Cursor, OpenCode, Grok (via Claude compatibility), Gemini, Copilot CLI, Pi, Amp, Kilo. Scan can read OpenCode and Grok locally; upload to Helm Web is still Claude + Codex. Claude desktop / ChatGPT app as wrap targets are not built.
